# 待校准队列：采纳落点与跨项目 UX

## 背景

Epic #755 交付了待校准队列（`/intake`），但实际使用中暴露四个问题：

1. 采纳后任务创建了却没有真正开跑，界面只显示"已采纳"，看不出卡在哪
2. 采纳只能新建任务，不能把这条消息交给一个已有任务（含已完成任务）重新执行
3. 队列页必须先用下拉选项目，默认只看第一个项目；缺少"待处理 / 历史"的区分
4. 状态只有待处理与已忽略，缺少"已采纳"
5. 队列条目无法删除
6. 重连后飞书回放的历史消息会再次触发任务

## 目标

- 采纳的每一步失败都可见，不再出现"显示已采纳但没执行"
- 采纳时可选「新建任务」或「本项目已有任务（含已完成）」
- `/intake` 默认跨项目展示待处理项并按项目分组，可切换历史
- 三态：待处理 / 已采纳 / 已忽略
- 支持单条与批量的队列条目删除（只删记录，不动已创建的任务与事件）
- 超过时效窗口的消息只记录不执行

## 时效窗口

- 触发时间取**平台发送时间**（飞书 `message.create_time`），取不到才回退到到达时间
- 默认 10 分钟；`NIUNIU_INTAKE_STALE_AFTER_MINUTES` 可覆盖，`0` 关闭
- 超时的触发照常写 `intake_events`，决策记为 `ignore` + `reason_code=stale`，
  永不执行；这样回放不会建任务，但审计链仍完整

## 主动员工只提议

旁听模式的定时分析（消息数阈值 + 静默期）**不再直接建任务**：发现的工作一律写成
待校准决策，必须由用户采纳后才执行。`observe` 与 `auto` 都记录（auto 也只记录、
不执行），`off` 与暂停状态不记录。这样"用户没操作就不启动"对所有入口成立。

## 来源开关与会话模式

- 项目设置 → 任务来源：每个来源只有一个**关闭 / 启用**全局开关
  (`intake_settings.enabled`)。关闭时该来源完全停用；不再有项目级默认模式
- IM 会话只有两种应答方式：

  | 应答方式 | @ / 私聊 | 群里普通消息 | 后台分析 |
  |---|---|---|---|
  | 仅响应（默认） | 执行 | 忽略 | 不做 |
  | 自动化 | 执行 | 命中规则且未超上限 → 执行；未命中 → 待校准 | 结果进待校准并提醒 |

- 移除「员工模式」「绑定方式（意图路由 / 钉死任务）」；固定任务改用 `/use #id`
- 非 IM 来源：启用后沿用其已存储的 mode（新来源默认观察）
- 后台分析的触发条件：**30 条未分析消息** 或 **最早一条已积累 30 分钟**，
  两者满足其一即触发；没有任何消息时跳过，不消耗模型调用

## 待校准的消费

一次自动执行会把该会话中尚未处理的待校准建议一并纳入本次工作，并在执行成功后
把这些建议标记为**已处理**（`intake_decisions.consumed_at`），每条只会被消费一次。
待处理列表只显示未消费的条目；已消费的进入历史。

手动采纳（`/intake` 页面确认）只执行被选中的那一条，**不消费**其他待校准消息：
同会话里剩下的建议保持待处理，用户仍需逐条决定。

## 迁移

- `intake_settings.mode='off'` 视为关闭（仅首次加列时回填）
- `intake_mode`：`off`/`inherit` → `respond`，`observe`/`auto` → `auto`（旧列默认改为 `respond`）
- `agent_mode` 不再参与决策；`ReceiveAll` 改由自动模式决定

## 非目标

- 不新增执行状态机（执行中/失败不作为状态展示）
- 不改动 accept/resume 的自动判定逻辑（auto 模式仍需要它区分新建与续接）
- 不引入跨项目选择任务

## 设计

### 1. 采纳落点

采纳请求新增可选 `target_issue_id`：

- 未传 → 维持现有行为（按 resolver 的决定新建或续接）
- 传了 → 强制走续接语义：把消息投递到该 issue 的工作空间，并记录
  `intake_decisions.issue_id / workspace_id`

已完成任务被选中时只投递并记录，**不重开卡片**、不改 issue 生命周期。
若该 issue 没有工作空间，返回明确错误，由用户改用「新建任务」。

### 2. 投递失败必须可见

`deliverToWorkspace` 从"只写 warn"改为返回错误：

- 采纳链路把错误上抛，API 返回 5xx/4xx
- `executed` 不被置 1，条目保持「待处理」，可以重试
- 前端 toast 显示错误

### 3. 状态

状态由现有字段推导，不新增列、不做迁移：

| 状态 | 条件 |
|---|---|
| 待处理 | `executed = 0 AND decision IN ('accept','resume')` |
| 已采纳 | `executed = 1` |
| 已忽略 | `decision = 'ignore'` |

历史视图在「已采纳」条目上显示执行落点链接（`#issue 标题 / workspace`）。

### 4. `/intake` 信息架构

- 默认「待处理」：跨项目、按项目分组、无需下拉；无待处理的来源/项目不显示
- 顶部切换：`待处理` / `历史`
- 历史：已采纳 + 已忽略，按项目分组、时间倒序
- 项目下拉保留为可选筛选，默认「全部项目」
- 列表不展示 accept/resume 分类；详情保留「系统建议：续接 #N（可改）」

### 5. 采纳弹窗

- 两个选项：新建任务（默认）/ 选择已有任务
- 任务选择器：本项目任务、按最近活跃排序、支持标题搜索、包含已完成
- 选中后展示其工作空间状态；无工作空间时禁用并提示

## 测试

- 后端：accept with target（有工作空间 / 无工作空间）、投递失败不置 executed、状态推导
- 前端：分组渲染、历史切换、任务选择器搜索与已完成任务、错误提示
